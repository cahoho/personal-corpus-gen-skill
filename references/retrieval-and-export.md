# 记忆检索、调用与出库

## 基本原则

- 用户可以给任何 AI 文件访问能力并用于个性化聊天；这不是对每个工具自动生效的权限，也不意味着有文件访问功能的工具一定遵守规则。
- 区分：检索是寻找文件，调用是向当前模型提供记忆，导出是生成可携带副本，上传/分享是向其他接收方发送。每一步都检查实际边界：云端模型接收上下文也可能构成外发。
- 当前用户请求优先；历史记忆是可能有时间与证据限制的辅助信息，不高于用户当下的澄清。事实缺失就承认未知，不从安静、单次发言或 AI 旧回答推断。

## 逐层检索

1. 确认用户许可的 Vault 路径及模型数据去向，读取 `00 Start Here.md` 和 `02 Self/Privacy & Boundaries.md` 中的规则；存在与本 Skill 不兼容的用户规则时以用户明确要求和安全边界为准，必要时先询问。
2. 先用主 MOC、路径、别名和当前任务关键词定位主题；仅限非私密文件。工具的检索范围要显式排除 `07 Privacy/`。如无法确保排除，不执行该检索，改为逐个打开明确允许的文件。
3. 读取相关笔记中最小必要的条目，再按需跟踪事件、项目和来源。注意 Markdown 的 `[[wikilink]]` 不是通用 Markdown 链接，不假定非 Obsidian 工具会自动展开。普通 MOC 不能保证覆盖全部内容。
4. 遇到私密笔记：先判断当前任务是否确有必要；必要时向用户说明目的和精确读取范围，得到明确同意后才读取必要内容。私密 MOC 自身亦受限。不要借检索、嵌入、摘要或引用绕过限制。
5. 按相关性、来源、依据、适用时间和用户允许范围挑选最小信息。输出时区分用户自述、观察和推断；不适用、缺时、冲突的信息必须说明；用户未要求引用时无需在每句话附出处，但应能追溯。
6. `last_mentioned` 只反映已处理且时间已知的资料。仅在用户询问或当前任务确需时计算间隔，说明覆盖范围；不据此自动提醒、判定项目关闭或推断用户改变。

## 跨 AI 的上下文

- 本地有文件能力时，给予用户许可的实际路径并按上述规则读取；无文件访问能力时，由用户选择提供经审阅的最小 Markdown 摘要或主题包。
- 同一 Vault 的文件夹、字段和 MOC 仅是约定，不是加密或技术访问控制。若用户将整个 Vault 提供给 AI、搜索索引、插件或同步服务，服务在技术上可能读取私密区，无法由此 Skill 保证限制生效。建议用户核对授权与同步范围，不把 Markdown 规则说成隔离技术。
- 一般个性化聊天按需读取协作偏好，不默认为每次对话复制所有 Profile；重要事实可带日期和出处，但不把整个语料作为提示词重复发送。

## 导出流程

1. 确认目标、接收者、用途、数据去向、内容范围和输出位置；生成的本地文件与对外发送分开确认。未经授权不能上传。
2. 默认排除 `07 Privacy/`。即使用户希望完整迁移，也要清楚说明是否包括私密内容及风险。必要时仅在具体授权范围内纳入部分私密内容。
3. 检查正文、标题、别名、文件名、链接目标、引用、嵌入、来源标识、附件及元数据，防止非内容字段泄露；剔除无关内容和被删除的记录。
4. 检查输出是否暴露其他人的隐私、推断是否被描述为事实、陈述是否过时。对于 Markdown 以外的使用环境，按需展开必要的 wikilink 并附上下文，避免输出悬空链接。
5. 向用户提供导出范围及风险摘要；只有经确认才创建或发送。明确已发出的副本、服务端缓存及其他设备备份不能由删除 Vault 自动撤回。
